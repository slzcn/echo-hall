# Echo Hall 页面结构诊断与精简地图

> 更新时间：2026-07-29（阶段 A/B 后）
>
> 目标：让 `index.html` 的结构、动态 DOM、脚本模块和浮层层级可定位、可拆分、可验证；不再靠在万行文件里盲搜。

## 1. 当前规模

- 单文件约 9900 行，由 HTML、CSS、内联 JavaScript 组成。
- 三个主场景：`#enter`、`#lobby`、`#hall`。
- HTML 最大静态嵌套约 8 层，核心问题是横向广度与动态生成结构，而不是静态 DOM 过深。
- 主业务脚本约 7400 行，约 300 个顶层函数。
- 阶段 A 已将 33 个散落浮层归拢到三个语义容器：
  - `#fx-bg`：背景与氛围层；
  - `#fx-ix`：互动与全屏特效层；
  - `#fx-modal`：弹窗、抽屉与通知层。
- `body` 顶层主要容器已从 19 个降至 6 个。
- 阶段 B 已删除 11 个零引用死函数；函数值传参（如 `map(fn)`、`on(..., fn)`）纳入死代码核验，禁止只按 `fn(` 判断。

## 2. 固定浮层结构

详细 z-index、opacity、pointer-events、background 见：

- [`fixed-layer-map.md`](./fixed-layer-map.md)

结构约束：

1. 新背景效果必须进入 `#fx-bg`；
2. 新互动特效必须进入 `#fx-ix`；
3. 新弹窗、抽屉、toast 必须进入 `#fx-modal`；
4. 禁止继续向 `body` 顶层直接追加业务浮层；
5. 同一 z-index 段新增元素前，先检查 `fixed-layer-map.md`，避免再制造堆叠冲突。

## 4. 动态 DOM 是嵌套审计重点

静态 HTML 中仅有少量“单子元素容器”；真正的结构复杂度主要由 JavaScript 模板动态生成：

- 消息气泡与富媒体消息；
- BGM 菜单、播放状态与曲库；
- 召唤／成员列表；
- 漂流瓶、塔罗、分享卡片；
- KO、互动和世界频道横幅；
- 抽屉、设置项和账号信息。

因此结构精简不得只扫描静态 HTML。每个动态模板改动必须完成：

1. 找到生成函数及全部 CSS 选择器；
2. 记录当前 DOM 层级与拟拍平层级；
3. 搜索 `querySelector`、`closest`、`children[n]`、`:scope >` 等结构依赖；
4. 单模板、单提交修改；
5. CDP 在真实场景中 dump runtime DOM 并验证交互。

## 5. 拆文件边界

真正拆分内联脚本时，按依赖从低到高推进，不按行数机械切割：

1. `core/theme.js`：主题、模式、场景基础工具；
2. `features/bgm.js`：BGM、曲库、播放状态、Web Audio；
3. `features/chat-render.js`：消息构建、富媒体、历史分批渲染；
4. `features/chat-input.js`：发送、发言模式、语音、神曲、斜杠命令；
5. `features/interactions.js`：长按环、KO、合体、粒子与互动特效；
6. `features/room.js`：大厅、进入／离开房间、presence、订阅；
7. `features/account.js`：注册、登录、找回、个人空间；
8. `features/keyboard.js`：visualViewport 与弹窗键盘跟随；
9. `app.js`：状态组合、事件绑定与启动。

拆分约束：

- 先显式列出模块输入／输出，禁止把闭包变量直接变成新的 `window.*` 全局污染；
- 每次只拆一个边界，保留原行为；
- 同步更新 `sw.js` 预缓存、Pages 部署文件清单与版本号；
- 每次拆分后运行 CI、CDP 场景测试、线上 curl 验证；
- 数据库 schema、业务行为和视觉样式不与拆文件混改。
