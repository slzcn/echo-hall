# Echo 回声厅 · 站点整体健康度指标体系

> 目标：从「能不能打开」升级到「整个站点是否健康运行」——覆盖可用性、性能、后端链路、实时通信、存储、AI 业务体验（对话反应速度、歌曲/BGM 生成质量）。
> 原则：只监测/告警，绝不自动改功能代码；涉及费用/副作用的项严格控频、可控、自动清理。

---

## 一、指标分层总览

| 层 | 关注什么 | 采集方式 | 自动化程度 | 成本/副作用 |
|----|---------|---------|-----------|------------|
| L0 可用性 | 页面能否打开、版本一致 | HTTP + CDP 白屏 | 全自动 30min | 零 |
| L1 性能 | 首屏/加载/内存/DOM 趋势 | CDP 采集 | 全自动 30min | 零 |
| L2 后端链路 | Supabase REST/RPC/Realtime/Storage | 只读探测 | 全自动 30min | 零 |
| L3 消息闭环 | 发→存→实时投递→读回 | 探测房真实写读 | 全自动 6h | 极低（探测房自删） |
| **L4 AI 对话反应速度** | 灵魂 AI 回复时延与产物 | 探测房触发 eh-soul-tick | 半自动（控频） | **有：AI 调用+写库** |
| **L5 歌曲/BGM 生成质量** | 生成成功率/耗时/音频客观质量 | 存活+历史采样 / 低频真生成 | 分档（见下） | **真生成有费用** |

## 二、逐项指标定义

### L0 可用性（全自动·零成本·已上线）
- 主页 HTTP 状态码 = 200
- 主页响应时间（阈值：>6s 记 slow）
- `ver.txt` 版本号存在且与 `index.html` 的 `BUILD_VER`、`sw.js` 的 `SW_VERSION` 三处一致（掉版/部署失败检测）
- 关键 JS 字节完整：`app.js` / `keyboard.js` / `dm.js` 可达且非空
- 主页壳标记 `id="hall"` + `BUILD_VER` 存在（页面结构损坏检测）
- CDP 白屏检测：无头 Chrome 加载真实页，`#hall` DOM 是否渲染

### L1 性能趋势（全自动·零成本·已上线）
- 首屏 DOMContentLoaded / load 耗时
- JS 堆内存 usedJSHeapSize（趋势）
- DOM 节点总数（趋势·内存泄漏征兆）
- console.error / 未捕获异常 / Log.error 计数（噪声过滤 ERR_ABORTED/canceled）
- **告警策略**：连续 3 次 load>10s、连续 3 次首屏 index>6s、连续 6 次堆内存单调增长≥30MB、连续 6 次 DOM 节点单调增长≥1000 才告警（避免单次抖动误报）
- 最近 48 样本存 `memory/echo-health-trend.json`

### L2 后端链路（全自动·零成本·已上线）
- Supabase REST 握手可达 + 响应时间
- Realtime WebSocket 握手成功
- 官方房列表 `eh_rooms` 可查
- RPC 延迟：`eh_public_recent(rid,lim)`、`eh_room_souls(rid)`（阈值 >3s 记 slow）
- 4 个 Edge Function 存活 + 鉴权门有效：`eh-sing-cover` / `eh-bgm-gen` / `eh-admin-api` / `eh-soul-tick`（用无 token 预期返 401 验证「在线且鉴权有效」，不真跑）
- 母版 manifest 可取 + 真实 MP3 Range 采样（4KB）验证 Storage 可读

### L3 消息闭环（全自动·极低成本·已上线）
- 固定匿名探测身份 + 固定私密探测房 `__EH_SYNTHETIC_PROBE__`
- 闭环步骤：刷新 session → Realtime 订阅 → 主动断线 → 重连+重订阅 → 写 1 条 `[EH_PROBE:<run_id>]` → REST 读回 → Realtime 同 ID 投递验证 → 服务端严格硬删除 → 查零残留
- 指标：写库耗时、重连耗时、REST 读回成功、Realtime 投递成功、清理成功、残留数=0
- 清理安全：同时绑定固定 room+固定 uid+`[EH_PROBE:` 前缀+本轮消息 ID，单轮最多删 20 条；清理失败则停止后续写入并告警

### L4 AI 对话反应速度（★本次新增·涉及费用）
**候选指标：**
- 灵魂 AI 首字/整段回复时延（从触发到消息落库的耗时）
- 回复是否成功产生（有无产物、是否报错）
- 回复内容基本健康度（非空、非报错串、长度合理）
- 触发到 Realtime 投递的端到端时延
**成本控制方案（三档，等主人选）：**
- A｜只测 `eh-soul-tick` 在线 + 鉴权（零成本，不真跑 AI）
- B｜探测房内每天 1-2 次真实触发一次灵魂回复，测真实时延与产物，自动清理
- C（推荐）｜日常只测存活，AI 对话时延每天真实采样 1 次拿趋势

### L5 歌曲/BGM 生成质量（★本次新增·真生成有费用）
**客观可测指标（不靠人耳）：**
- 生成成功率（发起→拿到可播放文件的成功比例）
- 生成耗时（发起到文件就绪）
- 文件完整性：HTTP Range 可取、Content-Length 合理、时长/码率达标
- 音频客观质量：峰值电平（是否爆音削顶）、RMS（是否过轻）、静音比例（是否哑掉/空文件）、采样率一致性
**分档方案（等主人选）：**
- A｜不真生成，只监测 Edge 存活 + 抽样已有历史歌曲文件可播放（HTTP Range + 时长/码率），零新增费用
- B｜每天/每周极低频真生成 1 首，用上述客观音频指标判合格，自动删探测产物
- C（推荐）｜自动只测客观项（成功率/耗时/文件完整/不爆音/不哑），主观「好不好听」由主人偶尔人工抽听

## 四、边界铁律（不可越）
1. 只监测/告警，**绝不自动改 js/*.js、绝不 git push 功能代码**；功能 bug 走「告警→人分析→改→ci-check.sh 门禁→主人真机验收」。
2. **不擅自真调付费 AI（MiniMax）**——L4/L5 真生成必须在主人选定档位、控频、探测房内、自动清理的前提下进行。
3. 凭据只从 `~/.openclaw/credentials/` 读，chmod 600，不进 git、不输出。
4. 探测产物（消息/歌曲/session）用固定 marker 严格清理，绝不扩大删除范围。
5. 视觉/键盘类仍只能真机验收，监测不替代。
