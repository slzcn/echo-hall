# Echo Bug 诊断单：离房快照复制完整消息流

## 1．用户旅程
300 条复杂消息房间离开 → 应快速返回大厅并保留轻量回房快照，不出现同步序列化尖峰。

## 2．稳定复现
离房直接读取 `_st.innerHTML`，同步序列化全部消息；持久化虽裁 30 条，内存 roomSnap 仍保留全量。

## 3．单一根因假设
内存快照与持久化快照使用不同裁剪策略。

## 4．验证方法
新增快照旅程：内存和持久化都最多保留最近配置数量，并保留必要终态／游标；旧全量 innerHTML 必红。

## 5．回归矩阵
- 少量消息
- 300 条消息
- 快速回房
- 最旧游标
- 未完成文本兜底

## 6．修复结果
新增 `journey-room-snapshot.js`，先在旧实现上确认全量 `_st.innerHTML` 契约失败。离房内存快照现在与持久化策略一致，只序列化最近 30 条消息；`echoState` 同步裁到这些消息的 mid，避免把全房互动状态继续留在内存。`oldestId` 改为裁剪后首条消息的 id，保证快速回房后“加载更早”从可见快照边界继续，不跳过被裁掉的中间消息；无法取得首条 id 时才回退原游标。

状态不变量：少于 30 条时完整保留；超过 30 条时只留尾部；未完成文本先用原始文本兜底；快照游标对应快照首条；回声状态只保留快照内消息。

本地验证：旧实现该 journey 必红；修复后 journey 与 JS 语法检查通过，并已接入 `scripts/ci-check.sh`。
