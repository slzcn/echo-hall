# 数据刷新并发与历史状态

## §1 现象
连续下拉可并发执行多轮版本检查和软刷新；消息尾部补拉使用全局锁，A 房补拉占锁时 B 房补拉会被直接丢弃；历史加载没有统一可访问的 busy 状态。

## §2 稳定复现
并发调用 `doRefresh()` 两次会调用两次 soft refresh。A 房 `refreshSnapshotTail` 延迟期间进入 B 并触发补拉，旧 `_snapTailBusy` 令 B 直接 return 且无补跑。

## §3 单一根因假设
刷新协调器缺少明确 single-flight 状态：下拉无锁，尾部补拉用跨房全局布尔锁且不记录 pending。

## §4 不变量
同一次下拉只执行一个刷新；不同房补拉互不阻塞；同房重入合并并在当前轮完成后补跑一次；历史加载期间 `aria-busy=true`，结束必恢复。

## §5 修复
下拉模块增加 `refreshing`；尾部补拉改为按 rid 的 `{busy,pending}` Map；消息流增加 log/live 语义和 busy 状态。

## §6 验证
新增刷新协调旅程，含旧实现反证。

## §7 结果
待门禁回填。
