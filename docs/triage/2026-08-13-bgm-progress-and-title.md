# 诊断单: 作曲期间无进度提示 + 兜底曲名不够好

- 日期: 2026-08-13 17:00 CST
- 现象:
  1. 房间 BGM 菜单里"请灵魂制作一首…"点后, 菜单被收起、只有一条一闪而过的 toast, **展开菜单
     时那行文案没变**, 用户以为没触发→反复点击。后端虽有 `_ehBgmGenerating` 锁挡住重复
     生成, 但 UI 不透传状态, 体验上仍是"没反应"。
  2. 兜底曲名池含"留给自己的一首""说不清的心情""当下这一刻"这类**流水/口语短句**,
     出现即显得敷衍, 不像策展命名。

## 单一根因

### 问题1: UI 缺少"作曲中"的原地状态
- `sendBgmGen` 只发 toast, 不通知 BGM 菜单更新自己的入口行。
- 菜单展开时那行(`bgm-gen-row`)始终渲染为"请灵魂制作一首…", 未订阅生成中状态。

### 问题2: 兜底词库品质
- `bgmGeneratedTitle` 命中意象走 `BGM_TITLE_MOODS` 策展名(质量 OK), 但**兜底池**
  (第 5183-5188 行的 return pick 列表)里塞了几个流水句, 尤其"留给自己的一首"太直白。

## 单变量修复(拆两处, 互不干扰)

### A. 菜单行状态化
- `sendBgmGen` 开始时 dispatch `window` 事件 `eh:bgm-generating-changed` (detail:{on:true});
  finally 里 dispatch `on:false`。
- `buildBgmMenu` 渲染 `.bgm-gen-row` 时读 `window._ehBgmGenerating`:
  - 生成中: 文案 "🎼 灵魂正在作曲…", 加 `.disabled` class, `data-action` 移除。
  - 空闲: 保持原文案 "请灵魂制作一首…" + `data-action="gen"`。
- 点击处理里再多一道防线: `.bgm-gen-row.disabled` 或 `_ehBgmGenerating` 直接 return + toast。
- 事件监听: 顶层挂一次 `eh:bgm-generating-changed` → 若当前 BGM 菜单开着, 重绘那一行。

### B. 曲名池升级
- 从兜底 return pick 里剔除: "留给自己的一首" "说不清的心情" "当下这一刻" "此刻回声"(过于口语)。
- 换成有意象、2-6 字为主的短句(与顶部策展名同风格): 例
  · 通用兜底: 光的褶皱 / 一寸夜色 / 未寄之信 / 心事微光 / 无题小调 / 半个回声
  · 深夜/电台: 午夜回声 / 凌晨电台 / 独自频率
  · 技术/代码: 代码微光 / 编译夜色 / 屏幕深夜
  · 虚空/回音: 星际回声 / 宇宙耳语 / 银河尾音
  · 私密: 耳边低语 / 只说给你 / 门后小语
- 曲名规范硬约束:
  · 长度 2-8 字(超过一律回兜底, 不做截断残句)——已有, 保留。
  · **禁量词开头/结尾**(一/首/曲/个/来 等)——已有 `^一/首/曲/…$` 判空, 保留。
  · **禁流水词**(留给自己的一首/说不清的心情/当下这一刻/此刻回声/什么什么的)——本次剔除。

## 验证

- 行为测试(A):
  1. 生成中调 `sendBgmGen` → 触发 `eh:bgm-generating-changed on=true`。
  2. 重绘菜单时 `.bgm-gen-row` 文案含"灵魂正在作曲"、无 `data-action="gen"`。
  3. finally 后 `on=false`, 重绘恢复原样。
- 行为测试(B):
  1. 传空/流水描述 → 兜底返回值∈新池且不含黑名单词。
  2. 传"深夜电台"→ 命中意象走策展名。
  3. 长度 2-8 字。
- CI: bash scripts/ci-check.sh 全绿。
