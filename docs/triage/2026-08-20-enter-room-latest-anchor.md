# Echo 进房未定位到最新聊天内容

## 现象
进入聊天室后，聊天记录没有直接停在最新位置，页面会持续滚动一段时间；最新内容判断还需要覆盖游戏卡片等非 `.msg` 内容。

## 根因假设（单一）
进房时历史消息分批渲染、游戏卡片/牌桌内容异步插入与 `ensureBottom` 并发。`ensureBottom` 在容器高度短暂不变时就判定稳定并结束，后续非 `.msg` 内容继续撑高；同时前置的 `scrollStream()` 可能使用平滑滚动，造成“先滚到一处、再继续滚”的视觉过程。虽然 `scrollHeight` 本身包含所有子节点，但进房落底时机和滚动行为没有统一收口。

## 修复方案
增加进房专用的无动画、一次性稳定落底策略：在消息/游戏内容完成当前批次后，按整个 `#stream` 的 `scrollHeight` 直接定位；稳定窗口内只用瞬时 `scrollTop`，不调用 smooth。把稳定判定改为连续多次检查，避免游戏卡片、字体、图片等异步内容刚插入后提前结束。新增旅程测试，验证最新位置取整个消息流而非仅 `.msg`，并验证进房落底不使用平滑滚动。

## 验证
运行专项旅程、JavaScript 语法检查及完整 CI。
