# 安卓折叠屏 PWA 输入框键盘顶沿错位

## §1 现象

- **设备**：安卓折叠屏（小米 18 Fold 展开态）
- **运行环境**：Android PWA，覆盖式软键盘，VirtualKeyboard API 不提供几何值
- **触发步骤**：进入 Echo → 打开私信或聊天室 → 聚焦输入框 → 弹出系统输入法
- **预期结果**：输入框容器底部贴在键盘顶沿，输入框完整可见。
- **实际结果**：私信输入框能上移但底部少数像素；聊天室输入框没有完整弹到键盘上方。
- **关键链路**：`innerHeight`／`visualViewport.height` 不变，`VK.boundingRect.height=0`，依赖无信号估算。

## §3 单一根因假设

**根因**：无信号兜底按可视屏高的 38％估算键盘高度，在该折叠屏的实际键盘高度上偏小，导致容器底沿仍落入键盘覆盖区；聊天室没有额外安全余量，因此表现更明显。

证据：真实 viewport 与 VK 均无变化时只能走估算；已有空 resize 修复已保留估算但仍出现固定少量错位。

## §4 修复方案

- 仅调整 `js/keyboard.js` 主聊天室与 `js/dm.js` 私信的无信号兜底系数：38％→39％。
- 真实 viewport/VK 信号路径不变；收键盘、旋转、折叠展开逻辑不变。
- 增加旅程测试，验证无信号路径保留更大安全余量，旧系数必红。
- 回滚：恢复两个文件中无信号估算系数，并同步回退版本号。

## §8 真机四组数据推翻系数微调 → V62 策略级重写（2026-08-14 10:11）

### 主人真机四组结果（唯一验收标准，CDP 桌面模拟不作数）
- 展开态 PWA · 私信 ✅（横竖）／聊天室 ❌ 竖屏 · ✅ 横屏
- 折叠态浏览器 · 私信 ❌（横竖）／聊天室 ❌（横竖）

### 结论：38%→39% 方向本身错
同一份系数四组结果四种表现 → 系数不是根因。上一版用 CDP 桌面模拟当「已修复」验收是误报绿（模拟不了折叠屏浏览器地址栏收展、竖屏真实键盘高、各家 WebView 键盘几何）。铁律：Echo 键盘/布局改动只用真机多场景数据验收，CDP 仅作代码事实层检查。

### 真根因
- 私信：`min(innerHeight, vv.height)` 读真值几乎不走估算 → 展开态稳；折叠浏览器崩，因 `_baseH` 被地址栏收展的 innerHeight 波动污染（把中间态当新全高）。
- 聊天室：`baseFullH − 估算键盘` 双变量减法，baseFullH 非落键盘真全高（竖屏地址栏/折叠几何）+ 39%×屏高 ≠ 真键盘高 → 一起偏 → 竖屏错、横屏对、折叠双错。

### V62 修复（策略级，不动系数）
1. 聊天室 `visibleHeight()` 对齐私信：优先直接取 `min(innerHeight, vv.height)`；只在两信号都未缩（`vis >= full-4`，真覆盖式 IME）才从全高减 VK/估算；已缩就用真可视高，杜绝双减。
2. 私信 `_baseH` 收紧：无键盘态候选全高需稳定 ≥300ms 才落地，且只在「稳定的更大全高」上抬升，防折叠浏览器地址栏动画污染。
3. 旅程 `scripts/journey-kb-ime-visual-gap.js` 重写为策略断言 + 数值反证（旧无条件减把已缩真值 470 硬砍到 439、少 31px，正是错位来源；新策略保留 470）。
