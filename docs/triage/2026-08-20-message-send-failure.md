# 消息发送失败诊断单

## §1 现象
普通文本消息先乐观渲染并清空输入框；数据库写入失败时仅弹出错误，气泡仍留在消息流中，用户无法判断是否发送成功，也无法原地重试。

## §2 稳定复现
通过对 `sb.from('eh_messages').insert` 注入失败响应，当前实现会保留 `local_*` 气泡、清空输入框，并只调用 toast；因此可稳定复现“假成功”。

## §3 单一根因假设
发送流程没有失败状态机：乐观气泡没有记录可重试 payload，失败分支没有将气泡标记为失败，也没有恢复输入内容。

## §4 约束与不变量
- 乐观气泡只能在成功确认或 Realtime 同步确认后转为正式消息。
- 失败时原文必须可见、可重试，不得静默丢失。
- 同一发送意图不得因重复点击产生两条数据库消息。
- 房间切换后，旧房发送结果不得写入新房。

## §5 修复方案
为每次发送生成唯一本地 ID，并保存待发送 payload；增加失败样式和重试入口；异常路径用 `finally` 释放发送状态；重试时固定原房间并拒绝跨房。数据库当前未确认存在 `client_nonce` 字段，因此不冒险写入未知字段，幂等由函数入口、唯一 local id、Realtime 真 id 回填去重和重试按钮禁重入共同保证。

## §6 验证
`node scripts/journey-message-send-failure.js`：覆盖失败原文保留、失败状态、重试 payload、切房拒绝、异常释放；旧实现反证稳定红。全量门禁由 pre-commit 执行。

## §7 结果
发送失败不再保留“像成功”的普通气泡；原文留在失败气泡内并可原地重试，离开原房后拒绝误发。
