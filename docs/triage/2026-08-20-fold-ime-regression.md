# Echo Bug：折叠屏无信号输入法再次遮挡输入框

## §1 现象（Reproducibility）

- **设备**：安卓折叠屏混合指针设备（具体机型待真机日志补充）
- **运行环境**：安卓 PWA／覆盖式输入法
- **触发步骤**：
  1. 进入聊天室；
  2. 点击主输入框；
  3. 输入法弹起但 `visualViewport`、`innerHeight`、`VirtualKeyboard.boundingRect` 均无变化；
  4. 输入框仍落在输入法覆盖区域内。
- **预期结果**：无几何信号时启用折叠屏备用估算，输入框位于输入法上方。
- **实际结果**：当前布局控制器运行，但无信号百分比估算被条件挡住，`#hall` 保持全高，输入框被遮挡。
- **修前视频/GIF**：未取得真机动态录屏；本单记录为线上回归分析，未将静态截图当作稳定复现证据。

## §3 单一根因假设

- **本次假设根因**：`137999b` 将无信号估算资格限定为 `hover:none + pointer:coarse`，导致“有触摸能力但 pointer:fine、且 hover:none”的折叠屏混合设备无法进入 39% 估算；该条件与 `usesSoftKeyboardLayout()` 的触摸设备判定不一致。
- **证据链**：
  1. `137999b` 新增 `allowNoSignalEstimate()` 并包住原有估算分支；
  2. 同一提交允许 `hasTouch()` 设备进入键盘布局控制；
  3. 折叠屏混合指针可满足触摸设备但 pointer:fine，现实现估算被跳过；历史 `65b81b5` 明确该兜底用于折叠屏无信号输入法。
- **可以证伪它的实验**：将 `allowNoSignalEstimate` 临时改为“触摸能力 + 无悬停”，在相同无信号条件下，旅程应由旧实现红变绿，同时带悬停硬件键盘场景仍不估算。
- **证伪结果**：未证伪，继续修复。

## §4 修复方案

- **动到的文件**：`js/keyboard.js`、`scripts/journey-kb-mixed-input.js`、`scripts/ci-check.sh`、版本三件套。
- **方案**：把无信号估算资格从“必须 coarse”改为“触摸设备且 hover:none”。这样覆盖 pointer:fine 的折叠屏混合设备，同时保留有 hover 的硬件键盘设备不因 focus 误缩。
- **影响**：Android 折叠屏／混合输入设备；桌面及带 hover 的硬件键盘设备不变。
- **回滚方案**：回退本原子提交。
