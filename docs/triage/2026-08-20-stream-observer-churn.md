# Echo Bug 诊断单：打字机触发高频全流布局检测

## 1．用户旅程
多条灵魂长消息连续打字 → 页面应平滑；回到最新按钮与历史锚点仍正确。

## 2．稳定复现
消息流 MutationObserver 监听 characterData；逐字 textContent 更新每 18～55ms 都触发 rAF，执行布局读取与可见消息遍历。

## 3．单一根因假设
回到最新监听把字符变化与结构／尺寸变化等价处理。

## 4．验证方法
新增契约：Observer 不监听 characterData；新消息节点仍触发，图片／卡片尺寸变化用 ResizeObserver 补齐；旧实现必红。

## 5．回归矩阵
- 新消息追加
- 打字机更新
- 图片／音频卡后加载撑高
- 用户翻历史
- 回到底部

## 6．修复结果
新增 `journey-stream-observer.js`，先在旧实现上确认 `characterData:true` 契约失败。消息流 MutationObserver 现在只监听结构变化，不再因打字机逐字更新触发全流布局判断；新增 ResizeObserver 观察现有与后续加入的顶层消息行，图片／卡片异步撑高时仍经同一个 rAF 节流入口复判“回到最新”和滚动锚点。

状态不变量：新消息追加仍触发复判；纯文本字符变化不触发布局扫描；顶层消息尺寸变化触发低频复判；所有入口共用单个 rAF 合并同帧事件。

本地验证：旧实现该 journey 必红；修复后 journey 与 JS 语法检查通过，并已接入 `scripts/ci-check.sh`。
