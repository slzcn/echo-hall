# Echo Bug 诊断单：大厅标题上方水平明暗切割

## §1 现象（Reproducibility）

- **设备**：用户移动端宽屏截图；本地以同截图尺寸 1716×486 CSS px、DPR 2 复现
- **运行环境**：日间模式，大厅页
- **触发步骤**：
  1. 进入大厅日间模式。
  2. 观察「回声厅」标题正上方至官方频道之间的背景。
  3. 可见一条笔直的水平明暗接缝；用户红圈标注区域尤其明显。
- **预期结果**：顶部背景从系统栏到大厅内容连续、柔和，无可识别的水平切割。
- **实际结果**：`#edgeFade` 顶部渐隐在 120px 结束，透明度斜率从持续变化瞬间变为 0；叠加 `.bg-grid` 与 `.bg-orb` 后形成水平明暗接缝。
- **修前截图**：用户消息原图 `om_x100b69ae93c9f870dd10867a21876af`；本地基准 `/tmp/eh_base.png`。

## §2 稳定复现

- ✅ 用户截图可见静态接缝，不依赖动画瞬间。
- ✅ 本地 CDP 以同宽高、DPR 2、日间大厅连续复现。
- ✅ 通过增强对比图 `/tmp/eh_base_contrast.png` 可稳定看到顶部渐隐结束带。
- **说明**：这是静态 CSS 背景合成问题，不需要键盘运行时数值；视频不比静态截图增加信息。

## §3 单一根因假设（Single Hypothesis）

- **本次假设根因**：`#edgeFade` 的顶部线性渐变在 `transparent 120px` 处结束，渐变斜率突然归零，导致该水平位置与下层网格／光斑产生明暗导数断点。
- **证据链**：
  1. 用户确认切割是直线，排除 `.bg-grid` 椭圆 `mask-image` 的弧形边界。
  2. 代码中唯一覆盖全宽、在标题上方具有固定水平边界的背景层是 `#edgeFade`，顶部透明终点为 120px。
  3. CDP 单变量实验：只隐藏 `#edgeFade`，该接缝消失、网格直接延伸到顶部；只隐藏 `.bg-grid` 产生的是网格消失，不是同一变化。
  4. 将 `#edgeFade` 临时改成长距离渐隐后，增强对比图中 120px 的收口带消失。
- **证伪实验**：不改文件，仅通过 CDP 覆盖 `#edgeFade` 的 `display`／`background`，固定其他背景层不变并截图对比。
- **证伪结果**：✅ 假设未被证伪，继续修复。

## §4 修复方案（Fix Plan）

- **动到的文件**：`index.html`；本诊断单。
- **动到的模块/行号**：顶部背景 `#edgeFade`（约 L196-L202）。
- **方案**：把 0→120px 的短线性收口改为多段缓出渐隐：顶部继续保持实色，随后逐级降低不透明度，并把尾部拉长；最后一段以低透明度缓慢归零，避免斜率突变。底部渐隐不动。
- **影响范围**：所有平台的日间／夜间背景；只改变装饰层，不影响布局、点击、键盘、滚动和房间状态。
- **历史回归检查**：保留 `#edgeFade` 顶部实色起点，不撤销其消除系统栏黑边的原用途；不触碰 `#soundwave`、`moodAura`、`.bg-grid`。
- **回滚方案**：回退本次 CSS commit 即可。
